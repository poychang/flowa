# Flowa

**Flowa** 是一套可安裝為 PWA 的多人即時協作畫布，讓團隊在同一個空間中繪圖、整理想法、建立流程，並直接圍繞畫布內容展開討論。

## 名稱由來

`Flowa` 是由概念名稱 **FlowCanvas** 演化而來；其中 **Flow + Canvas** 分別代表：

- **Flow**：代表流程、思考脈絡，以及團隊討論的推進。
- **Canvas**：代表不受版面限制、可自由延伸的共同畫布。

這個名稱直接傳達 Flowa 的核心概念：**在畫布上共同討論流程，讓想法自然流動並逐步成形。**

> **Flowa — Where ideas flow into action.**

## 產品願景

Flowa 希望讓遠端與現場團隊不必在簡報、聊天訊息與紙本白板之間來回切換，就能透過一個跨裝置的視覺工作空間，共同完成腦力激盪、流程設計、系統架構討論與會議整理。

## 核心功能

首個可用版本（MVP）預計包含：

- 無限畫布的平移、縮放與框選操作
- 自由繪圖、文字、基本圖形、連接線與箭頭
- 可變更文字及圖形的顏色
- 流程圖節點的快速建立與連接
- 多人即時共同編輯與遠端游標
- 參與者名稱、顏色與連線狀態
- 分享連結與訪客加入
- 畫布自動儲存與重新連線同步
- PNG、SVG 或 JSON 匯出
- PWA 安裝、基本離線開啟與本機草稿
- 桌面、平板與觸控筆操作

詳細範圍、里程碑與驗收條件請參閱 [plan.md](./plan.md)。

## 低成本架構（已確認）

Flowa 採「本機儲存優先的 PWA＋極薄的免費協作後端」。單人繪圖、儲存、離線與匯出由前端完成；多人模式才連線至房間轉送服務。不承諾雲端永久保存。

| 層級 | 技術與部署 | 責任 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 畫布 UI、同步整合與匯出 |
| 畫布 | Excalidraw | 繪圖、文字、圖形、顏色與連接線 |
| 本機儲存 | IndexedDB | 本機文件、恢復資料與待同步變更 |
| PWA | Manifest + Service Worker | 安裝、靜態資源快取、離線啟動 |
| 靜態託管 | Azure Static Web Apps Free | 提供前端檔案，不承載 WebSocket |
| 協作後端 | Node.js / TypeScript + Socket.IO，Azure App Service F1 | 房間憑證驗證、Presence、訊息轉送；僅暫存於記憶體 |

Excalidraw 元件本身不附完整協作功能。優先參考官方協作實作與 excalidraw-room，仍需整合物件合併、刪除、重連與本機儲存；不是安裝套件即可完成。

MVP 不使用 tldraw、PostgreSQL、Redis、Blob Storage、獨立 ASP.NET Core API 或付費即時服務，也不導入 WebRTC／TURN。

## 成本與容量

- 以免費配額內的服務費為零為目標，不包含開發、維運、網域或超出免費方案的額外服務費用。
- 協作測試目標為 2～4 人。F1 每個執行個體最多 5 條同時 WebSocket 連線，是全部房間合計，不是每房間 5 人；多開分頁可能增加連線。
- F1 每日 CPU 配額為 60 CPU 分鐘，不等於只能運作一小時；不支援 Always On、沒有 SLA，需接受冷啟動、重啟及配額耗盡時協作不可用。
- 容量不足時保留本機編輯與匯出，明確提示協作暫時不可用；不自動升級付費方案。
- 部署前重新核對官方配額與目標區域供應情況，詳見 [plan.md](./plan.md) 的來源與成本控制。

## 儲存與分享的限制

| 功能 | MVP 語意 |
| --- | --- |
| 自動儲存 | 儲存於目前瀏覽器的 IndexedDB，不等同雲端備份 |
| 分享連結 | 加入即時房間，不是永久文件網址 |
| 重新連線 | 合併仍在線參與者或尚存記憶體狀態的資料 |
| 所有人離開／後端重啟 | 房間狀態可能消失；持有本機副本的人須重新開房分享 |
| 換裝置 | 透過在線協作者取得資料，或匯入 JSON |
| 本機資料被清除 | 若沒有其他副本或 JSON 備份，無法保證復原 |

顯示「已存於此裝置」與「協作同步完成」兩個獨立狀態。JSON 是可編輯備份，PNG／SVG 用於分享成果，不能取代完整備份。離線首次造訪、未曾快取的畫布或資源不保證可開啟。

## 快速開始與狀態

目前已有 **Phase 0 單人畫布原型與元素同步 PoC**：11 項單元及 14 項 Chromium 測試通過。尚未接入正式多人房間、完成 Phase 0 全部驗收或部署。執行 `pnpm install`、`pnpm dev` 啟動；執行 `pnpm build` 編譯。實作範圍與限制見 [DEVELOPMENT.md](./DEVELOPMENT.md)。

單人模式須能在協作後端未設定或不可用時獨立運作。正式託管使用 HTTPS／WSS，瀏覽器直接連至 F1，不依賴 Static Web Apps 的 API 代理。
