# ADR 0001：有版本檢查的本機草稿與匯入恢復

狀態：已採用；2026-09-22。

## 決策

IndexedDB `flowa` 升級至 v2。`boards/draft` 從舊 JSON 字串漸進遷移為 `{ schemaVersion: 1, revision, scene }`；讀取舊字串時視為 revision 0，首次成功寫入才轉換格式。不認識的版本或損毀內容不覆寫。

每次寫入在同一筆 readwrite 交易讀取 revision，比對呼叫端持有的版本。若其他分頁已先寫入，拒絕舊版本並要求使用者先匯出分歧副本，不使用最後寫入覆蓋。

匯入流程先驗證並載入 JSON，再等待既有自動儲存完成，最後以同一筆交易保存原稿到 `recoveries` 並替換草稿。交易完成後才換掉編輯器，避免 `resetScene` 中間的空白狀態被儲存。恢復副本最多 3 份，每份以畫布 10 MiB 上限控制，UI 可下載最近一份。

自動儲存每次延遲 500ms，序列化交易；只有交易完成才顯示成功。失敗保持 dirty 狀態，可明確重試。頁面關閉前提示未儲存變更，但不能保證瀏覽器強制終止時保存最後一次操作。

本機及 JSON 備份保留刪除標記。Excalidraw 匯出序列化器預設過濾已刪除物件，因此 `serializeScene` 使用其 appState/files 輸出，但保留原 elements 陣列供後續同步恢復。

## 驗證與限制

fake-indexeddb 單元測試：v1 遷移、同時寫入、交易回滾、大小限制、保留副本上限與未知格式保護。

Chromium 操作測試：實際繪圖、重新載入、JSON/PNG/SVG、獨立瀏覽器還原、刪除標記、錯誤匯入、配額錯誤提示與重試、多分頁衝突。

這仍是單一裝置的單一草稿；沒有雲端備份。最多 2,000 個物件／10 MiB 的 JSON 匯入限制包含刪除標記。IndexedDB 清除後無法保證復原；恢復副本也受瀏覽器配額約束。沒有將此次本機多分頁衝突保護冒充跨裝置協作。
