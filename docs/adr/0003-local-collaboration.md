# ADR 0003：本機多人房間與同步協定 v2

狀態：已實作並完成本機測試；2026-09-23。沿用 ADR 0002 的 Excalidraw 物件合併規則，正式畫布改用本 ADR 的協定。舊 v1 adapter 僅保留在 PoC 測試入口。

## 權限與狀態

採用 Node.js / TypeScript + Socket.IO WebSocket-only relay。REST 建房回傳三組獨立 256-bit 隨機權杖：管理者可編輯及關房、編輯者可編輯、唯讀者只能接收與傳送游標。relay 在握手驗證房間與角色，後續每次操作再次檢查權限；sender 與 room 由連線決定，客戶端不能在增量中指定。

房間資料僅在記憶體：憑證雜湊、成員、sequence、各物件版本／nonce／內容雜湊／大小、有限未確認增量、短暫快照片段。relay 不把完整場景當作權威文件，也不使用 Redis、資料庫或雲端物件儲存。所有編輯者離線後需要有副本的人建立新房間。

Origin 精確比對、全服務連線上限 4、建房與封包速率限制、有界緩衝及大小檢查減少資源濫用。這不是公開服務的完整防護方案；HTTP origin 不等同身分驗證，憑證持有人可以讀取或依角色改寫房間，沒有帳號撤權、審計或端對端加密。

## 初次加入與重連

1. 本機資料以 `draft` 或 `room:<id>` 隔離。已有副本者先 flush IndexedDB，再交易式保存 checkpoint；寫入失敗時不套用遠端快照。
2. 握手成功後 `sync-start` 指派已就緒編輯者作來源。未初始化房間由管理者以本機內容播種；已初始化卻無來源時回報 `no-snapshot-source`。
3. 來源等目前互動、待套用增量及本機未確認變更處理完成，再以已套用 sequence 建立快照。SHA-256、總位元組數與片段數先以 metadata 傳送，再逐片傳送。
4. relay 檢查來源擁有權、片段順序、大小、digest 與 schema，完整驗證後才轉送。加入者以新同步世代隔離舊傳輸，同時暫存新增量。
5. 編輯者用公開 `reconcileElements` 合併快照與離線變更；唯讀者採用遠端快照。接著按 sequence 消化快照基準之後的增量。
6. `sync-ready` 必須追上 relay 當前 sequence 才變為就緒。來源中斷／逾時不會視為空白成功；用戶端最多自動重試兩次後顯示錯誤。

未取得過房間副本的訪客不把初始空白內容寫入 IndexedDB、不允許匯出或以空白重開房。此設計避免失效連結偽裝為成功載入。

## 增量、確認與衝突

增量只傳改變的物件，使用 `{protocol:2,id,elements}`。relay 指派單調 sequence 與 sender。第一層 RPC ACK 只表示服務接受；每個當時已就緒的參與者送出 `applied` 後，relay 才送 `sync-ack` 讓來源推進已同步版本。離線成員不再阻擋確認；後續重連走快照恢復。

客戶端最多一包在途、5 秒未確認重送同一 id、最多重送三次。relay 保存最近 256 個訊息指紋以去重；已完成確認的重送會再次回覆 `sync-ack`。快照追上 sequence 也視為已套用對應的較早增量。

正在拖曳、繪製、調整尺寸或輸入文字時先暫存遠端增量。遠端套用使用 `CaptureUpdateAction.NEVER`，保留本機 Undo/Redo 行為。合併依 id、version，再以較小 versionNonce 決勝；同 version/nonce 卻內容不同直接停止同步。排序 index 修復會成為下一輪增量。這是整個物件層級的衝突處理，不是字元級多人文字 CRDT，並行輸入仍可能一方勝出。

## 有界資源

| 項目 | 限制 |
| --- | --- |
| 已驗證 WebSocket | 全服務 4 條 |
| 房間 | 最多 32 個，8 小時到期、空房 10 分鐘回收 |
| 場景 | 2,000 個物件（含 tombstone）、10 MiB |
| 封包／快照片段 | 256 KiB／192 KiB，最多 64 片 |
| 收件／服務未確認緩衝 | 64 包或 1 MiB |
| 快照／未套用確認期限 | 15 秒／15 秒 |
| 增量／Presence／單連線所有事件 | 每秒 12／5／80 次 |
| 建房 | 每 IP 每分鐘 5 次、全服務每分鐘 20 次 |
| 恢復資料 | 每畫布 3 份，全資料庫 12 份或 30 MiB |

刪除物件仍佔場景容量，避免 tombstone 遺失後舊物件復活。達上限時顯示錯誤並保留可匯出的副本，不悄悄丟棄資料。共享 Zod schema 僅允許文字與向量物件並驗證核心幾何、版本、索引與綁定欄位；未知 Excalidraw 屬性保留以維持相容。

## 驗證邊界

真實 relay 搭配 Chromium 測試初始同步、同時變更、唯讀、重連、快照交錯、綁定拖曳、房間副本隔離、relay 重啟，以及 500／2,000 物件。長時間測試使用真實 Socket.IO Node 用戶端，不包含持續瀏覽器繪製。

本機延遲與 CPU/RSS 無法證明 Azure F1 配額符合需求。PWA、Safari/iPad/觸控筆、實際鎖屏恢復、WAN 延遲與雲端部署仍需下一階段驗收。細節與量測數字見 [驗證報告](../testing/local-collaboration.md)。
