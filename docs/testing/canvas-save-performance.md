# 畫布自動儲存：序列化成本改善

日期：2026-09-30。來源基底 `bb930bf`，程式修改 `7f5b6f5`。本次降低完整場景 JSON 的重複工作；固定產物交錯短測的整輪操作時間下降，但長任務與縮放尾端延遲沒有一致改善，繪製停頓仍待處理。

## 發現與修改

舊版每次 Excalidraw `onChange`（包括平移／縮放）都呼叫 `serializeScene`，先產生完整 JSON、parse，再包含刪除標記重新 stringify，最後才由 Autosave 比較字串是否改變。2,000 物件的獨立 CPU profile 確認這條呼叫路徑有顯著成本。

新版先比較元素參考、版本與 nonce、刪除狀態、排列、檔案 metadata／data URL，以及由 Excalidraw 自己篩選的持久化 app state。純檢視通知不排入儲存；真實變更只排入延後的序列化函式。Autosave 保留首個 500 ms 計時截止，不因新通知一直重設，避免連續編輯無限延後保存。主執行緒繁忙時實際執行仍可能晚於 500 ms，這不是硬性延遲保證。

切換畫布、背景保存、更新與重連前的 `flush()` 仍會讀取並等待最新內容；寫入中的新變更繼續依序處理。序列化或寫入失敗會保留待存資料，不顯示保存成功，並可明確重試。匯入交易、恢復副本、多分頁 revision 衝突與 tombstone 保留規則不變。

## CPU 取樣

固定 2,000 物件、20 秒持續操作，修改前後各一次。獨立使用 `PERF_PROFILE=1`，不混入下方時間基準。相同 Windows 工作站、Intel i7-8650U、Chromium 140.0.7339.186、1440×1000、DPR 1、正式產物；無 relay，Service Worker 被阻擋。

| CPU profile | 修改前 | 修改後 |
| --- | ---: | ---: |
| 取樣涵蓋時間（含 idle） | 20,946.60 ms | 21,430.97 ms |
| 完整操作輪數 | 7 | 6 |
| `serializeScene` 含子呼叫取樣時間 | 3,386.07 ms | 105.00 ms |

上述是各次執行中此函式的累計取樣時間，並非單次輸入延遲，也不是完全相同操作輪數的微基準。此結果支持「完整 JSON 重複工作下降」，不能直接換算使用者操作加速百分比。修改後 profile 仍有大量 `drawImage`、canvas `save`、`getContext` 與 Excalidraw 繪製呼叫。

對照同次 bundle 的函式位置確認來源：舊版 `y1` 是 `serializeScene`、`kh` 是 Excalidraw serializer；新版相對應為 `ef`／`Mh`。取樣含子呼叫時間重疊，不能將 wrapper 與 serializer 時間相加。原始壓縮 profile：[修改前](canvas-save-profile-before.cpuprofile.gz)、[修改後](canvas-save-profile-after.cpuprofile.gz)；解壓後可用 DevTools 載入，或由 `node scripts/summarize-cpu-profile.mjs <檔案>` 重算摘要。

## 一分鐘時間對照

不啟用 profiler，500／2,000 物件各執行一次至少 60 秒；同一工作站依序執行，沒有隔離 CPU、固定溫度或隨機化順序。所有匯入、真實繪圖、移動版本、保存、匯出及重載後再次匯出的資料斷言通過，沒有 page error／crash。

| 場景 | 前／後操作輪數 | 前／後 RAF p95 | 前／後 long task p95／最大 |
| --- | ---: | ---: | ---: |
| 500 物件 | 42／38 | 16.80／16.80 ms | 112／134 → 367／406 ms |
| 2,000 物件 | 24／20 | 33.30／33.40 ms | 485／524 → 874／1,011 ms |

**這組對照的操作時間沒有改善，部分數值變差。** 不能僅根據序列化成本下降，宣稱畫布已變流暢或消除卡頓。也不能沒有證據就將差異全部歸因於環境。

## 重複短測

另以 2,000 物件、每次至少 20 秒，修改前後各重複三次。仍為先前版、再新版的順序執行，不是交錯或隨機化試驗；各次只有 5～7 輪，p95 很接近最大值。

| 版本／次數 | 秒數／輪數 | 平移來回 p95 | 縮放來回 p95 | Long task 最大 |
| --- | ---: | ---: | ---: | ---: |
| 前 1 | 21.25／6 | 1,967.57 ms | 1,840.69 ms | 816 ms |
| 前 2 | 23.36／6 | 2,279.74 ms | 2,167.16 ms | 967 ms |
| 前 3 | 20.82／5 | 2,235.88 ms | 2,435.70 ms | 1,024 ms |
| 後 1 | 23.90／7 | 1,890.55 ms | 2,585.68 ms | 1,097 ms |
| 後 2 | 22.24／5 | 2,927.44 ms | 3,763.67 ms | 1,910 ms |
| 後 3 | 21.37／5 | 2,028.25 ms | 3,896.21 ms | 1,758 ms |

六次資料保護檢查皆通過。舊版本身也比先前的一分鐘測試慢，說明結果存在波動；但新版縮放數值持續較差，不能用環境波動解釋掉這個發現。因此追加以下固定產物交錯比較，沒有刪除較差的結果。

所有一分鐘、重複短測及 profile 的原始指標集中於 [JSON 證據](canvas-save-performance.json)，保留每次時間、操作輪數、來源、產物雜湊、heap、錯誤及場景雜湊；兩個原始 profile 的解壓內容與 `.gz` 檔案 SHA-256 亦分別記錄於其中。

## 固定產物交錯比較

將兩份完整正式產物保留在不同目錄，使用 `PERF_ARTIFACT` 按「前、後、後、前」執行，各至少 20 秒、2,000 物件；測試期間不重新建置，也沒有同時執行其他本機回歸。兩份內容雜湊與前面的數據一致。四次資料、匯出與重載檢查全部通過；完整原始數據記錄於 JSON 的 `alternating20Seconds`。

| 順序／版本 | 秒數／輪數 | 每輪平均 | 平移來回 p95 | 縮放來回 p95 | Long task 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1／前 | 20.96／8 | 2,619.83 ms | 1,550.40 ms | 1,241.08 ms | 525 ms |
| 2／後 | 20.68／9 | 2,297.23 ms | 1,381.09 ms | 1,121.68 ms | 468 ms |
| 3／後 | 20.34／9 | 2,260.52 ms | 1,352.78 ms | 1,116.97 ms | 488 ms |
| 4／前 | 21.92／9 | 2,435.68 ms | 1,520.46 ms | 983.62 ms | 411 ms |

合併各版本的操作時間／輪數，前版約 2,522 ms／輪、後版約 2,279 ms／輪，這個小樣本約下降 9.7%。此處一輪包含來回平移、縮放、一次移動與測試驅動；不是 GPU 幀率或單一操作延遲。改善沒有一致反映於縮放 p95 或 long task 最大值，且只有四次短測，不代表所有情況或裝置。初期較慢的整輪結果未在這次交錯比較重現，仍保留作為後續更長、隨機化比較的依據。

## 產物與重現

修改前正式產物的 SHA-256 為 `f843c3b14106b7c254be1910d6a0d419b6d580d83ca9b405ff23edc568a910f8`，與既有歷史基準一致；修改後為 `5cf0590e40d5d9784e417305e834314a0f784249a443d13703a5fe146db3f1f8`。雜湊計算方式見效能測試的 `buildHash`。

修改前的一分鐘測試是在編輯新原始碼期間，以尚未被覆蓋的舊正式產物執行，因此原始 JSON 的 `dirtyPaths` 非空。後續重複對照以基底的 App.tsx／autosave.ts 暫時建置，隨即還原目前原始碼；此時 `sourceCommit` 是測試 checkout，產品版本須依上述產物雜湊與本報告的基底判斷。修改後測試使用 `7f5b6f5`，相關來源乾淨。原始數據不修改這些欄位。

一般重現方式：在欲測版本建置正式產物後，依 [效能工具](browser-performance.md) 設定 `PERF_SECONDS`，明確關閉或啟用 `PERF_PROFILE`。重複短測使用 `pnpm test:performance --grep 2000 --repeat-each 3`。不要把目前 checkout 誤當成尚未重新建置的 dist 來源。

## 驗證與剩餘工作

本機 26 項單元測試、型別／正式建置與 34 項 Chromium 回歸通過。新增測試包含批次序列化、持續通知的截止時間、序列化失敗重試、寫入期間新編輯，以及元素／檔案變更偵測；既有瀏覽器回歸涵蓋資料恢復、儲存失敗、房間切換、離線修改與協作一致性。

`7f5b6f5` 的 [GitHub Actions](https://github.com/poychang/flowa/actions/runs/36689002128) 全部通過：26 單元、9 relay、4 HTTPS 工具、34 Chromium、20 Firefox／WebKit、3 混合裝置、2 效能短測、7 PWA、3 正式啟動，共 108 項測試，另有 2 組重連短測與型別／全部建置。

下一步定位縮放時的 canvas 重建／繪製成本，並做更長、隨機化的重複比較，確認尾端延遲與其他情境沒有退化；文字、箭頭、圖片內容與 Safari／iPad 實機仍需另外驗證。未更新第三方依賴、物件上限或宣稱整體效能驗收通過。
