# 協作斷線重連長測

更新日期：2026-09-29。此測試接續 [歷史持續連線量測](local-collaboration.md)，使用目前 relay 進行 2 人及 4 人各 30 分鐘的離線／重連負載。

## 執行方式

```sh
pnpm test:soak
```

預設同時執行兩個獨立房間與 relay，各 500 個物件，運行 1,800 秒；每隔 300 秒讓最後一位編輯者離線 10 秒。預期每組完成 5 次斷線重連。輸出預設為 `test-results/reconnect-soak.json`，不覆蓋已提交的歷史數據。

環境變數 `SOAK_SECONDS`、`SOAK_RECONNECT_SECONDS`、`SOAK_OFFLINE_SECONDS` 必須為正整數秒，測試時間須能涵蓋完整重連及收尾。`SOAK_OUTPUT` 可指定輸出 JSON 路徑。CI 採用以下短測設定，每組完成 2 次重連；短測不取代 30 分鐘實測：

```powershell
$env:SOAK_SECONDS = '24'
$env:SOAK_RECONNECT_SECONDS = '8'
$env:SOAK_OFFLINE_SECONDS = '2'
pnpm test:soak
```

重新執行完整測試時，請將上述環境變數設回 `1800`、`300`、`10`，或開啟未設定這些變數的新終端。

## 負載與判定

- 在線參與者各自修改不同物件，目標每秒一次增量、每秒四次游標通知。每次增量均透過真實 Socket.IO relay，接收者套用後回覆 ACK。
- 離線參與者停止發送訊息，在其本機測試場景修改自己的物件；其他參與者持續編輯。重連時確認離線期間確有在線更新。
- 快照傳輸前暫停產生負載並等待 ACK 清空，從在線來源傳送實際快照分片。接收端驗證 transfer ID、順序、數量、長度、SHA-256 與場景格式，再恢復版本較新的離線物件並透過 relay 發布。
- 每次重連檢查離線修改完整保留、所有場景一致；結束再次核對場景雜湊一致且沒有未確認增量。任何錯誤、未完成重連、資料不一致或 p95 ≥ 500 ms 都以非零狀態結束。

同步延遲從送出增量到收到 `sync-ack`；重連時間從開始建立新連線到快照恢復與離線修改全部確認。離線的 10 秒另行記錄，不混入正常增量延遲。各次快照傳輸期間暫停負載，因此不是快照與持續寫入交錯的壓力測試。

## 量測界線與可重現性

JSON 記錄來源提交、受測檔案的實際 SHA-256、來源是否有未提交變更、Node／平台、起訖時間、設定、每次重連及最終場景雜湊。來源雜湊涵蓋 relay、協定、測試工具、共用 helper、測試場景及 lockfile；檔案雜湊以執行環境的實際位元組為準，包含換行格式。

兩組在同一個 Node 行程執行。CPU／RSS 為兩個 relay 與六個測試用戶端的合計，只記錄一次，不能分攤為單一 relay 成本。RSS 每秒取樣並在結束補取樣，並非作業系統的精確歷史峰值。出站 payload 含快照、ACK、成員與游標，不含 HTTP／WebSocket framing、TLS 或完整握手成本。

測試位於 Windows loopback，沒有瀏覽器繪製、IndexedDB、正式前端同步狀態機、同物件衝突、全員同時離線、WAN 或 Azure F1。這些仍需各自的回歸／實機／目標環境驗收，不能從本次數據外推。
