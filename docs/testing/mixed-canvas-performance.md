# 混合內容與反覆停止縮放驗證

日期：2026-10-01。產品基底為 main `4071da3`（PR #11 已合併），量測工具提交 `c5ec26f`。本次擴充驗證，沒有修改產品繪製邏輯。

## 場景與方法

使用正式產物、Windows 的 headless Chromium、1440×1000、DPR 1；同一台 Intel i7-8650U 工作站，單一 worker 依序執行 500／2,000 物件，各至少 300 秒。沒有同時執行其他本機測試；GitHub CI 在遠端執行。這是各一組長時間樣本，沒有控制溫度或所有背景程序。

匯入 499／1,999 個物件，依序循環長方形、繁體中文文字、未綁定箭頭、橢圓與圖片，再用真實滑鼠畫一個長方形。500 物件場景匯入前四種類型各 100 個、圖片 99 個；2,000 物件場景分別為各 400 個及 399 張圖片。所有圖片引用同一個 32×32 紅藍 PNG，不代表不同大圖的解碼負載。文字及箭頭沒有容器／節點綁定；綁定語意由既有瀏覽器回歸覆蓋。

每輪執行平移來回、縮放來回及方向鍵移動所選物件。第 1 輪及每 5 輪另執行放大、等待 400 ms 與兩次 RAF，再縮回及相同等待，反覆觸發既有 300 ms debounce 後的快取重建；測試要求每個週期性停止樣本都有 canvas 建立。持續階段結束後再執行一次最終 probe。

`interactionSeconds` 包含週期性停止，`measuredSeconds` 再包含最後 probe。`stoppedZoomSamples[].milliseconds` 是來回命令與明確等待的總時間，不能當成純輸入延遲。整段 RAF／long task 採樣包含停止重繪，但沒有將個別 long task 歸因至特定操作。canvas 建立數不是存活數量或記憶體用量。

資料檢查包含匯入的文字、箭頭座標、圖片引用及檔案內容；持續操作後比對所有未修改物件、移動物件版本、完整場景匯出與重新載入後再匯出。圖片 ID、MIME type、data URL 須相同，忽略套件可能補入的存取時間 metadata。

## 重現

```powershell
pnpm install --frozen-lockfile

$env:PERF_WORKLOAD = 'mixed'
$env:PERF_SECONDS = '300'
$env:PERF_PROFILE = '0'

```

量測來源應先提交；原始 JSON 的 `dirtyPaths` 應為空。產品內容雜湊：`9746e61ffbc15af3b085a682ae63ab635213679b584438b842161e7dc63deec0`。本次只有測試／文件變更，重建產物與 PR #11 的內容雜湊一致。

## 五分鐘結果

兩組皆通過資料、檔案內容、JSON 匯出及重新載入檢查，page error／crash 為 0。兩組的相關來源 `dirtyPaths` 皆為空，原始紀錄見 [mixed-canvas-performance.json](mixed-canvas-performance.json)。已檢視 2,000 物件結束畫面，文字、箭頭、橢圓及紅藍圖片均有繪出；這不是逐像素視覺驗收。

| 指標 | 500 物件 | 2,000 物件 |
| --- | ---: | ---: |
| 持續操作時間 | 300.28 秒 | 300.59 秒 |
| 操作輪數 | 208 | 153 |
| 週期性停止來回次數（不含最後 probe） | 42 | 31 |
| 停止來回命令 p50 | 956.86 ms | 1,495.35 ms |
| 停止來回命令 p95 | 986.15 ms | 1,588.70 ms |
| 停止來回命令最大值 | 994.89 ms | 1,594.71 ms |
| RAF 排程間隔 p95 | 16.8 ms | 16.8 ms |
| Long task p95 | 137 ms | 416 ms |
| Long task 最大值 | 144 ms | 454 ms |
| Canvas 建立次數（含最後 probe） | 86,000 | 256,000 |

停止來回命令包含兩段各 400 ms 的明確等待，不可直接扣除 800 ms 當成重繪成本。RAF p95 低仍可能有少數長停頓；2,000 物件的最大 long task 為 454 ms，**停止後重建尖峰仍未解決**。每次週期性停止來回觀察到 2,000／8,000 次 canvas 建立，與既有小樣本 probe 的數量一致。尚未逐一對 long task 做 CPU 歸因。

## 自動化回歸

`c5ec26f` 的 [GitHub Actions](https://github.com/poychang/flowa/actions/runs/36818871637) 全部通過：116 項測試（26 單元、9 relay、4 HTTPS 工具、36 Chromium、24 Firefox／WebKit、3 混合裝置、4 效能短測、7 PWA、3 正式啟動），另有 2 組重連短測；凍結鎖檔安裝、型別與全部建置成功。本機正式建置及長方形／混合場景各兩項短測通過。

## 限制與下一步

這組結果用來檢查長時間混合內容的資料完整性與觀察停頓，沒有通過／失敗的速度門檻，也不代表效能已全面驗收。混合場景、週期性停止和先前純長方形短測不同，不能以兩者每輪時間推論改善或退步。JS heap 沒有強制 GC，首尾差值不能證明記憶體洩漏；RAF 不是 GPU 呈現幀率。

後續應在實際 iPad／Safari 與目標桌面裝置確認可接受的停止後延遲，再以相同混合場景做前後對照，評估如何分攤新倍率的快取重建。大量不同圖片、綁定流程圖與自由筆仍可另加負載場景；單人 PNG 支援不代表協作模式允許圖片。PWA、真實鎖屏與網路協作不屬於本量測。
