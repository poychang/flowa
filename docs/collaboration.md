# 本機協作操作與故障處理

更新日期：2026-09-23。此版本可在本機啟動真實 Socket.IO 協作；尚未部署 Azure，也沒有 PWA 安裝或離線啟動保證。

## 啟動

需求為 Node.js 24、pnpm 11。從專案根目錄執行：

```sh
pnpm install --frozen-lockfile
pnpm dev:all
```

前端為 `http://127.0.0.1:5173`，relay 為 `http://127.0.0.1:3001`。`GET /healthz` 回傳 `{"ok":true,"protocol":2}`。請使用終端顯示的位址；若 5173 已被占用，先停止占用該埠的開發服務，或另外設定一致的前端埠與 origin。

`pnpm dev` 僅啟動前端；沒有 `VITE_RELAY_URL` 時仍可單人繪圖、儲存與匯出。需要分開啟動時，可將 `.env.example` 複製成未追蹤的 `.env.local`，再各自執行 `pnpm dev:relay` 與 `pnpm dev`。

| 設定 | 預設／範例 | 用途 |
| --- | --- | --- |
| `VITE_RELAY_URL` | `http://127.0.0.1:3001` | 前端連線目的地；`dev:all` 自動提供，正式建置須另外設定 |
| `HOST` | `127.0.0.1` | relay 監聽介面 |
| `PORT` | `3001` | relay 監聽埠 |
| `ALLOWED_ORIGINS` | `http://127.0.0.1:5173,http://localhost:5173` | 精確 origin 清單，以逗號分隔、不含結尾斜線 |

預設只允許同一部電腦使用。若自行在受信任區域網路測試，須同時調整前端 Vite host、relay host、可到達的 `VITE_RELAY_URL`、origin 與防火牆；分享連結必須使用其他裝置可到達的前端網址。正式公開使用須配置 HTTPS/WSS，這次沒有提供公開部署設定或宣稱已完成安全稽核。

建置：

```sh
pnpm build
pnpm build:relay
node --env-file-if-exists=.env.local dist-relay/apps/relay/main.js
```

前端輸出在 `dist/`，relay 在 `dist-relay/`。relay 執行環境仍須有根目錄的 `package.json`（ES module）及 Node runtime dependencies。Vite 會在建置時讀取 `VITE_RELAY_URL`；建置後只改 relay 環境變數不會改變前端 URL。`pnpm preview` 的 origin 也須加入 relay 允許清單才能測試協作。

## 使用房間

1. 在單人畫布完成內容，輸入顯示名稱並按「建立協作房間」。建立前會驗證內容、完成本機儲存並留下恢復副本。
2. 管理者可複製編輯或唯讀連結。訪客加入時向在線編輯者取得初始內容；完成前畫布顯示等待提示。
3. 「已存於此裝置」表示 IndexedDB 已完成寫入。「協作同步完成」表示目前增量已由在線、已就緒的參與者套用；不代表雲端永久保存。
4. 「離開房間」回到原本單人草稿；「關閉房間」使所有房間連結失效，參與者保留已取得的本機副本。
5. 定期下載 JSON。PNG/SVG 可分享成果，不能替代可編輯備份。

房間期限為建立後 8 小時，空房 10 分鐘回收。全服務最多 4 條已驗證協作連線，包括管理者、編輯者、唯讀者及各分頁；最多 32 個暫存房間。畫布限制為 2,000 個物件（含刪除標記）及 10 MiB，單一封包 256 KiB。此版本多人模式只支援文字與向量圖形，不提供圖片、嵌入內容或多人 JSON 匯入。

編輯／唯讀權杖位於網址 fragment，握手才送往 relay；權杖是持有即授權的秘密，不應放進公開貼文。管理者憑證只由建立者保留於該分頁的 sessionStorage；管理者自身網址也具有管理權限。relay 保存權杖雜湊，不記錄或持久化原始權杖。這不是端對端加密，relay 能讀取轉送中的內容。

## 本機副本與故障

單人草稿使用 `draft`；每個房間使用 `room:<id>`。加入其他房間不覆蓋單人草稿。重連前先完成本機 checkpoint，成功才套用遠端快照；唯讀訪客以遠端內容為準，編輯者使用物件版本合併離線編輯。

每份畫布最多保留 3 份恢復資料，全資料庫最多 12 份／30 MiB（先刪較舊者）。這個限制僅涵蓋恢復歷史，房間目前副本仍保留。可用「匯出同步前副本」下載最近 checkpoint。清除瀏覽器網站資料會刪除副本，請先匯出需要的 JSON。

| 狀況 | 處理 |
| --- | --- |
| relay 暫時中斷 | 已取得內容的編輯者可本機編輯與匯出；自動重連時先備份，再同步 |
| relay 重啟／房間逾期／管理者關閉 | 房間無法恢復；按「以副本重新開房」，分享新連結 |
| 沒有在線編輯者提供快照 | 不用空白畫布取代文件；請持有副本的人重新開房 |
| 連線容量已滿 | 等其他分頁離開後重連；本機副本仍可匯出 |
| 儲存失敗、配額不足或多分頁版本衝突 | 先匯出目前內容；修正儲存問題再重試，避免直接重新整理遺失未存內容 |
| 相同版本卻有不同內容／大小超限 | 同步停止並提示，先匯出備份，縮減或人工整理後重新開房 |
| 快照來源離線、逾時或緩衝溢位 | 自動嘗試重新同步，重試仍失敗則顯示錯誤，可手動重連或另開房間 |

relay 僅保留版本摘要、有限未確認增量與傳輸期間的快照，不保存可隨時下載的完整文件。全員離線後即使房間尚未回收，也可能沒有來源可重新加入。不要把分享網址當成文件儲存網址。

## 驗證

詳見 [開發狀態](../DEVELOPMENT.md) 與 [驗證報告](testing/local-collaboration.md)。長時間測試不在一般 CI 中執行，可另行執行：

```sh
node --experimental-transform-types tests/relay/soak.ts
```

預設同時量測 2 人及 4 人各 30 分鐘，會覆寫 `docs/testing/relay-soak.json`。`SOAK_SECONDS` 可縮短為診斷用途；縮短結果不符合 30 分鐘驗收。
